# The guide to this app

Thursday reads this when the user asks about Thursday itself — what it can do, where
something is, why it behaved the way it did. It is written for them, not for whoever builds
the app: screens and settings, never code.

Read the one file that covers the question, then answer in a sentence or two. Say where a
screen is the way the user sees it — "Settings › Bots" — and never name a file from here.

| File | What is in it |
|---|---|
| `calls.md` | Calling her, what she does herself, how a call ends, the call's own settings |
| `bots.md` | Bots, the work they take, threads, questions, what they made |
| `memory.md` | What she keeps about the user, and how they change it |
| `setup.md` | Keys, models, skills, connected services, where the files live, what it costs |

Two things hold everywhere:

- **The screen is one page.** Her face in the middle starts and ends a call; the corner at the
  top right opens settings; the corner at the bottom right is where handed-over work shows up.
- **Work outlives a call.** Anything handed to a bot keeps running after a call ends, as long
  as the app is open in a browser tab.
